## 1. 视觉哲学

顶会流程图是「压缩后的视觉论证」，不是装饰信息图。一张合格图必须 3 秒内回答：
1. 输入是什么？ 2. 主要模块/阶段是什么？ 3. 新贡献在哪？ 4. 输出/如何训练评估？

**优先序**：紧凑科学清晰 > 海报漂亮；语义清晰 > 视觉炫技；科学可信 > 好看。

## 2. 画布与比例

| 项 | 值 |
|---|---|
| 横向画布 | 2.0:1 ~ 3.2:1（双栏方法图）；1.3:1 ~ 1.8:1（benchmark/agent 流程） |
| 外边距 | 宽 2-4%（窄但必须存在） |
| 区域 gutter | 宽 2-5% |
| 有效信息占画布 | 55-80% |
| 分区内部信息占比 | 60-85%（空洞则放大模块/展开行列/加语义小对象） |
| 根背景 | `reconstruct_1to1` 跟随参考图实测背景；仅 `publication_normalize`/profile 明确要求时用纯白 `#FFFFFF` |
| PNG 兜底 | 300-600 dpi；矢量 PDF/SVG 进 LaTeX 优先 |

- 禁止大框包小字（大容器 + 小模块/小字 = 坏密度）；容器/模块/字号/证据对象须同步缩放。
- 禁止大块装饰空白；空白只用于分隔区域。
- 禁止最终图底部独立「Legend / Notes / advantages」说明栏（页脚分裂失败模式）；legend 改成局部信息/路径说明/callout。

## 3. 四层层级

1. **宏观区域**（3-6 个）：`Input/Encoder/Retrieval/Training/Inference/Evaluation/Output/Reward/Tool Use/Data Construction`。
2. **模块**：简洁名词短语。好：`Task-Aware Retriever`；坏：`Process`/`Model`/`Step 1`。
3. **机制细节**：仅在解释创新机制时加 token/张量/矩阵/特征图/loss/公式。
4. **导航提示**：箭头/编号/图例/颜色标签，贴近解释对象。

## 4. 连接线规范

- 普通流程箭头优先水平/垂直直线或直角折线，不斜拉、不弯曲、不悬空、不穿过模块。
- 同一 pipeline 不混用多个主方向；反向箭头显式标注（gradient/feedback/reward/memory）。
- 表格/矩阵/token 行的「选择」用高亮单元格 + 整体边界输出，不从单元格斜拉箭头。
- 多路融合用明确 fusion/sum/concat 节点或「无箭头 bus」；输入可无箭头头，输出必带。
- 端点净空、lane gap、避免无意义交叉（科学拓扑必须交叉时先重排节点）。

## 5. 颜色

| 色 | 语义 |
|---|---|
| 浅蓝 | 输入 / visual encoder / 主模型容器 / 中性过程 |
| 浅绿 | 输出 / 成功预测 / memory / evidence |
| 浅黄 | prompt / query / task / goal |
| 浅橙 | training / reward / loss / evaluation |
| 浅紫 | language / LLM reasoning / token / attention |
| 灰 | frozen / baseline / external / inactive |
| 饱和红橙 | loss / error / warning / 关键创新 / selected token |

- 最多 4-6 种语义色；填充低饱和 pastel，高饱和只给贡献/loss/输出。
- 贡献高亮（彩色描边/`Ours` 标签/编号 callout/较粗箭头）；baseline 安静；不要全突出。

## 6. 文字

- 清洁 sans-serif；最多 2 种字体；粗体只用于区域标题/模型名/阶段标题。
- 字号四级：区域标题 > 模块标签 > 数据/箭头标签 > 图例。
- 双栏模块标签 ≥ 12-13 px；图内总标题 18-22 px（克制）。
- 文本外接框占模块宽 45-75%、高 25-60%；公式占框宽 55-90%、高 25-40%。
- 必须解释用 2-4 个短 bullet，禁段落；标签尽量水平对齐，缩放后仍清晰。

## 7. 密度与留白

- 密集但不随机；留白是 gutter/语义分组间距，不是虚线框内大面积空白。
- 重复内容用堆叠/省略号/brace/`N×` 抽象；每个密集簇有标题。
- 每个宏观区域至少 1 种「非盒子机制表达」（波形/频谱/token grid/状态轨迹/矩阵/局部网络/公式/微资产/证据小图）。
- 方法特异科学对象 **≥ 5 个**（否则判普通 PPT 流程图）。

## 8. 快速门槛（14 条，任一「否」即需改）

1. 3 秒内能否定位贡献？ 2. 阅读顺序清晰？ 3. 展示输入/方法/输出评估？ 4. 模块进宏观区域？
5. 箭头语义一致？ 6. 每色有理由？ 7. 最终论文宽度下可读？ 8. 像方法图非结果图集？
9. 最大分区被有效利用（非大框包小字）？ 10. 文字/公式/箭头/模块/小图无非语义重叠？
11. 公式来自 LaTeX 源（非位图/OCR/伪公式）？ 12. 本轮未让历史问题复发？
13. 机制小图真增强解释（非装饰贴片）？ 14. 公式框/fusion 节点满足 containment + 可读 + 连接语义？

## 9. 100 分量表

| 维 | 分 | 满分段 | 低段 |
|---|---|---|---|
| 贡献可见性 | 20 | 18-20 新模块居中且命名 | 0-7 换标题可套用 |
| 结构层级 | 15 | 13-15 有 3-6 宏观区域 | 0-4 box soup |
| 阅读顺序流向 | 15 | 13-15 不看 caption 可懂 | 0-4 混乱矛盾 |
| 科学完整性 | 15 | 13-15 数据/模型/目标/输出齐全 | 0-4 装饰为主 |
| 视觉语义 | 10 | 9-10 色/线/箭头/符号一致 | 0-2 无稳定视觉语言 |
| 字体标签 | 10 | 9-10 简洁可读技术准确 | 0-2 不可读/全是段落 |
| 密度控制 | 10 | 9-10 密度高且分组清 | 0-2 过稀或过挤 |
| 顶会适配度 | 5 | 5 放 CVPR/ICLR 旁可信 | 0 不像方法图 |

总分 100。通过建议：可读语义/结构层级/密度 ≥ 8 分，贡献可见性 ≥ 15 分。

## 10. 工作流模式（12 种，选型用）

1. 标准 Pipeline（输入→编码→Proposed Core→Head→输出+Loss）；2. Baseline vs Proposed 对照；
3. Training vs Inference 分离；4. 多模态中心枢纽；5. Agent Loop（含 memory/feedback 闭环）；
6. RAG 检索增强；7. Diffusion 生成框架；8. Benchmark/数据集构建；9. 共享 Backbone 模块化；
10. 双向耦合/反馈系统；11. Token/Feature Selection；12. 方程/程序搜索。

每个模式的详细画法见上游源文件 `workflow-patterns.md`；此处保留模式名供选型路由。

## 11. image2 阶段 vs 白盒重绘阶段 职责拆分（关键）

- **image2 阶段**：鼓励整体顶会感/机制小对象；允许局部轻插画化小元素（专业克制）；**不要**提前强制可编辑/全正交连线（否则压回普通框图）。只强制：科学事实、贡献位置、阅读顺序、不复制参考图。
- **白盒重绘阶段（draw.io/PPT）**：翻译成可编辑图；统一文字/对齐/颜色/线宽/边距/连接线；按 LaTeX 源重绘公式；决定哪些保留位图/重绘矢量；严格检查重叠/可读/导出稳定。
- 「禁止底部说明栏」是白盒阶段的硬规则，**不作为** image2 prompt 的硬负约束。

## 12. 常见失败模式（反例）

过于简单（课堂图）/ 过于拥挤（无层级）/ 过于装饰（图标抢方法）/ 过于文字化（段落替结构）/ 结果图过重 / 底部页脚分裂 / 过于对称（baseline vs proposed 同权重）/ 裁切随意（箭头标签贴边）/ 大框空洞（slide 占位符）/ 泛化（换标题可套任何论文）。
